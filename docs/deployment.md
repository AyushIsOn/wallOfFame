# Deployment

Wall of Fame runs as **one Render web service** plus a **Render PostgreSQL
database**. The service builds the frontend, then runs `node server/index.js`,
which serves the wall, the admin and the API.

## Before you start

You need:

- the repository on GitHub,
- a [Render](https://render.com) account,
- a password for the admins,
- optionally, an n8n instance and an LLM API key (Groq or OpenRouter) for AI
  bios.

Render's free tier is fine for trying it out. Know its limits before relying on
it ([Render's free-tier docs](https://render.com/docs/free), checked October
2026):

| Free tier | Effect here |
|---|---|
| The web service sleeps after 15 minutes without traffic and takes about a minute to wake up | The first visitor after a quiet period waits |
| **Free Postgres expires 30 days after creation**; 14-day grace period to upgrade, then it is **deleted** | All students and photos are lost unless you upgrade or move the data |
| Free Postgres: 1 GB, no backups, one per workspace | Roughly a few thousand students with photos; back up by hand (below) |

For a real launch, use a paid Postgres plan; the web service can stay free.

## Deploy on Render

### 1. Create the database

Render dashboard → **New** → **Postgres**. Pick a name and region (use the same
region for the web service), choose a plan, then **Create Database**. When it's
ready, copy the **Internal Database URL**.

`render.yaml` deliberately doesn't create the database: a workspace can only
have one free Postgres, and a blueprint that creates another fails.

### 2. Create the web service from the blueprint

Dashboard → **New** → **Blueprint** → connect the GitHub repo. Render reads
`render.yaml` and proposes one web service, `wall-of-fame`:

| Setting from `render.yaml` | Value |
|---|---|
| Build command | `npm ci && npm run build` |
| Start command | `node server/index.js` |
| Health check | `/api/health` |
| Node version | 22 |

### 3. Set the environment variables

Render asks for the variables marked `sync: false`. All of them are explained in
[configuration.md](configuration.md).

| Variable | Value |
|---|---|
| `DATABASE_URL` | The Internal Database URL from step 1 |
| `ADMIN_PASSWORD` | **Required.** A strong password. Without it, admin login is disabled in production. |
| `TOKEN_SECRET` | Generated by Render; leave it |
| `N8N_TAGS_WEBHOOK_URL` | Optional; add it later (below) |
| `VITE_GET_FEATURED_URL` | Optional: link for the header's GET FEATURED, e.g. your submission form |

Add `SEED_SAMPLE_DATA=false` under **Environment** if the real site should start
without the 25 sample students.

### 4. Deploy

Click **Apply**. The first build takes a few minutes. The log should end with:

```text
[db] seeded 25 sample students      (only if seeding is on and the table was empty)
Wall of Fame server on :10000
```

## After the first deploy

1. Open `https://<service>.onrender.com/api/health`. It should return `{"ok":true}`.
2. Open the wall at `https://<service>.onrender.com/`.
3. Open `/admin` and sign in with `ADMIN_PASSWORD`.
4. Import a small sheet, or the example from
   [`docs/examples/import-example.csv`](examples/import-example.csv), to check
   the pipeline. Its Riya Das photo URL points at `localhost`, so that one photo
   fails on Render. That's expected.
5. If the samples were seeded and you don't want them, remove them
   ([recipes.md](recipes.md#remove-the-sample-students)).

If something fails, see [troubleshooting.md](troubleshooting.md).

## Connect the AI workflow (n8n)

Without n8n, imports still work with a local fallback (shortened About,
keyword tags). For real AI-written bios:

1. Import `n8n/enrich.workflow.json` into your n8n instance, add the LLM API
   key, and activate it ([n8n/README.md](../n8n/README.md) has the steps).
2. Copy the webhook's **Production URL**.
3. Render → service → **Environment** → set `N8N_TAGS_WEBHOOK_URL` → **Save
   changes**. Render restarts the service.
4. In the admin, open a student, click **Generate** next to Tags, and check
   that the tags look LLM-made.

## Updating

- **Code:** Render auto-deploys every push to the branch it watches (normally
  `main`). The build runs `npm ci`, so dependencies always match
  `package-lock.json`.
- **Schema changes** apply automatically on boot (`migrate()` in
  `server/db.js` only adds tables and columns).
- **Downtime:** the server shuts down gracefully on `SIGTERM`, so in-flight
  requests finish (10-second cap).
- **Rollback:** Render → service → **Events** → pick an earlier deploy →
  **Rollback**. Free services can roll back to the two most recent deploys.
- **Environment changes** restart the service. Changing a `VITE_*` variable
  needs a new build: **Manual Deploy** → **Deploy latest commit**.

## Backups and the free tier

Free Render Postgres has no backups, and paid plans' backups are worth
supplementing before big imports. With the
[PostgreSQL client tools](https://www.postgresql.org/download/) installed, use
the database's **External Database URL** (Render → database → **Connect**):

```bash
# Back up everything, photos included (photos are in the database)
pg_dump "$EXTERNAL_DATABASE_URL" --format=custom --file=wall-of-fame-$(date +%F).dump

# Restore into a new, empty database
pg_restore --no-owner --dbname="$NEW_EXTERNAL_DATABASE_URL" wall-of-fame-2026-10-31.dump
```

To move off an expiring free database: create the new database, restore the
dump into it, set `DATABASE_URL` on the web service to the new Internal URL,
and let it restart.

## Custom domain

Render → service → **Settings** → **Custom Domains** → add the domain and create
the DNS record Render shows. TLS is automatic. The app has no hard-coded
hostnames, so nothing else changes.

The public wall can be embedded in another site with an `<iframe>`. The admin
page can't be: it sends `X-Frame-Options: DENY`.

## Other hosts

Any host that runs Node 20.12+ works:

```bash
npm ci && npm run build
DATABASE_URL=postgres://… ADMIN_PASSWORD=… TOKEN_SECRET=… PORT=8080 node server/index.js
```

- Put it behind HTTPS (a reverse proxy like Caddy or nginx, or the platform's
  load balancer), and set `TRUST_PROXY=1` if exactly one proxy sits in front.
- Without `DATABASE_URL`, data goes to PGlite in `PGLITE_DIR` on local disk.
  That's fine on a VM with a persistent disk, but on platforms with ephemeral
  disks (including Render) the data is lost on every deploy.
- The app keeps login rate-limit counters in memory, so run a single instance.

## Production checklist

- [ ] `DATABASE_URL` points to a paid (or backed-up) Postgres
- [ ] `ADMIN_PASSWORD` is strong and shared only with the admins
- [ ] `TOKEN_SECRET` is set (Render-generated)
- [ ] Sample students removed, or `SEED_SAMPLE_DATA=false` from the start
- [ ] `N8N_TAGS_WEBHOOK_URL` set and tested with **Generate**
- [ ] Students agreed to be shown; sensitive fields left empty (see [security.md](security.md#privacy))
- [ ] A backup was taken after the first real import
- [ ] `VITE_GET_FEATURED_URL` set if you have a submission form
